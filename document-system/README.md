# ระบบจัดเก็บเอกสาร

ระบบเว็บสำหรับจัดเก็บเอกสารภายในองค์กร เขียนด้วย PHP ธรรมดา (ไม่มีเฟรมเวิร์ก) ใช้ MySQL ผ่าน PDO และหน้าจอภาษาไทยด้วย AdminLTE 3

คลังนี้มีระบบปฏิทินอยู่แล้ว ระบบจัดเก็บเอกสารจึงอยู่ในโฟลเดอร์ `document-system/` และไม่ไปแก้โค้ดเดิม

## ความต้องการของระบบ

- PHP 8.0 ขึ้นไป พร้อมส่วนขยาย `pdo_mysql`, `fileinfo`, `mbstring`
- MySQL 5.7+ หรือ MariaDB 10.3+
- Apache 2.4 (แนะนำ) หรือ PHP built-in server สำหรับทดลอง
- เว็บเบราว์เซอร์รุ่นปัจจุบัน

## วิธีติดตั้ง

### 1. สร้างฐานข้อมูล

สร้างฐานข้อมูลชื่อ `document_archive` ด้วยชุดอักขระ `utf8mb4_unicode_ci`

ใน phpMyAdmin กด **New** แล้วตั้งชื่อ `document_archive` หรือปล่อยให้ไฟล์ SQL สร้างให้ ถ้าบัญชีฐานข้อมูลมีสิทธิ์ `CREATE DATABASE`

### 2. นำเข้า SQL

ใน phpMyAdmin เลือกแท็บ **Import** แล้วเลือกไฟล์ `document-system/database.sql`

ไฟล์นี้สร้างตาราง `users`, `categories`, `documents` และข้อมูลเริ่มต้น (ผู้ดูแล 1 คน และหมวดหมู่ตัวอย่าง) การนำเข้าซ้ำจะลบข้อมูลเดิมในตารางเหล่านี้

ถ้านำเข้าแล้วขึ้นข้อผิดพลาดเรื่องสิทธิ์สร้างฐานข้อมูล ให้สร้างฐานข้อมูล `document_archive` เอง เลือกฐานข้อมูลนั้น แล้วลบบรรทัด `CREATE DATABASE` กับ `USE` ออกก่อนนำเข้า

### 3. คัดลอกไฟล์ตั้งค่า

```bash
cp config.sample.php config.php
```

แก้ค่าใน `config.php`

- `db_host` โฮสต์ของ MySQL เช่น `127.0.0.1`
- `db_port` พอร์ต เช่น `3306`
- `db_name` ชื่อฐานข้อมูล `document_archive`
- `db_user` ชื่อผู้ใช้ฐานข้อมูล
- `db_pass` รหัสผ่านฐานข้อมูล

ไม่ต้องนำ `config.php` เข้า git

### 4. สิทธิ์โฟลเดอร์อัปโหลด

ไฟล์เอกสารถูกเก็บที่ `storage/uploads` ซึ่งอยู่นอกเว็บรูท `public/` และถูกปิดการเข้าถึงตรงด้วย `.htaccess` ผู้ใช้ของเว็บเซิร์ฟเวอร์ต้องเขียนโฟลเดอร์นี้ได้

Linux:

```bash
chmod 750 storage storage/uploads
chown www-data:www-data storage/uploads
```

เปลี่ยน `www-data` เป็นผู้ใช้ที่รัน Apache จริง ถ้าเครื่องใช้ชื่ออื่น

Windows / XAMPP: ให้สิทธิ์ Modify แก่ผู้ใช้ที่รัน Apache บนโฟลเดอร์ `storage\uploads`

### 5. ขนาดไฟล์ใน php.ini

ระบบรับไฟล์ได้ไม่เกิน 20MB ต้องตั้งค่า PHP ให้รับไฟล์ได้อย่างน้อยเท่านี้

```ini
upload_max_filesize = 20M
post_max_size = 25M
```

จากนั้นรีสตาร์ทเว็บเซิร์ฟเวอร์

### 6. เปิดเว็บ

ถ้าวางทั้งโปรเจกต์ไว้ในเว็บรูท (คู่กับระบบปฏิทิน) ให้เปิด

```text
http://localhost/<โฟลเดอร์โปรเจกต์>/document-system/public/
```

ถ้าชี้ DocumentRoot ไปที่ `document-system/public` ให้เปิดที่รากของโฮสต์นั้น

ทดลองด้วยเซิร์ฟเวอร์ในตัวของ PHP:

```bash
cd document-system
php -d upload_max_filesize=20M -d post_max_size=25M -S localhost:8080 -t public
```

แล้วเปิด `http://localhost:8080/`

## บัญชีเริ่มต้น

| ชื่อผู้ใช้ | รหัสผ่าน   | บทบาท        |
|-----------|------------|--------------|
| admin     | Admin@1234 | ผู้ดูแลระบบ |

ควรเปลี่ยนรหัสผ่านหลังเข้าสู่ระบบครั้งแรก โดยไปที่เมนู **ผู้ใช้งาน** แล้วแก้ไขบัญชี `admin`

รหัสผ่านนี้ระบุไว้ใน README เท่านั้น ไฟล์ SQL เก็บเฉพาะค่าแฮช

## การใช้งาน

- **ผู้ดูแลระบบ** เห็นแดชบอร์ด จัดการเอกสาร หมวดหมู่ และผู้ใช้
- **เจ้าหน้าที่** เห็นแดชบอร์ด จัดการเอกสารและหมวดหมู่ แต่เข้าหน้าผู้ใช้ไม่ได้
- แดชบอร์ดแสดงจำนวนเอกสาร จำนวนหมวดหมู่ และรายการที่อัปโหลดล่าสุด
- ค้นหาเอกสารได้จากชื่อเอกสาร เลขที่เอกสาร หมวดหมู่ ช่วงวันที่ และสถานะ พร้อมแบ่งหน้า
- อัปโหลดได้เฉพาะ `pdf`, `doc`, `docx`, `xls`, `xlsx`, `png`, `jpg`, `jpeg` ขนาดไม่เกิน 20MB
- ดาวน์โหลดได้เฉพาะหลังเข้าสู่ระบบ ผ่าน `download.php`
- การลบและการปิดใช้งานผู้ใช้จะถามยืนยันด้วย SweetAlert2 และผลลัพธ์สำเร็จหรือผิดพลาดแสดงด้วย SweetAlert2 เช่นกัน

## โครงสร้างไฟล์

```text
document-system/
  README.md
  config.sample.php
  database.sql
  includes/           โค้ดร่วม ปิดการเข้าถึงจากเว็บ
  public/             เว็บรูท (หน้า PHP, AdminLTE, SweetAlert2)
  storage/uploads/    ไฟล์เอกสาร อยู่นอกเว็บรูท
```

## แก้ปัญหาเบื้องต้น

- หน้าตั้งค่าขึ้นว่าเชื่อมต่อฐานข้อมูลไม่ได้: ตรวจ `config.php` ว่าโฮสต์ ชื่อฐานข้อมูล ผู้ใช้ และรหัสผ่านตรงกับ MySQL และนำเข้า `database.sql` แล้ว
- อัปโหลดแล้วขึ้นว่าไฟล์ใหญ่เกิน: เพิ่ม `upload_max_filesize` และ `post_max_size` ตามด้านบน แล้วรีสตาร์ทเซิร์ฟเวอร์
- อัปโหลดแล้วขึ้นว่าโฟลเดอร์เขียนไม่ได้: ตรวจสิทธิ์ของ `storage/uploads`
